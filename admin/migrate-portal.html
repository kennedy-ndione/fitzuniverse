Migration — Portail de candidature par défaut

Fait remonter programs.applicationUrl vers universities.applicationPortalUrl quand la valeur est partagée par tous les programmes d'une université (35 cas sur 36 constatés à l'audit), et ne laisse applicationUrl rempli que pour les vraies exceptions (ex. Politecnico di Milano : portail PhD distinct). Réservé aux administrateurs, non lié dans la navigation. À exécuter dans l'ordre des 3 étapes — l'étape 3 doit afficher 0 perte de données avant de considérer la migration terminée.

1Analyser (lecture seule, aucune écriture)

Calcule, pour chaque université, la valeur majoritaire de applicationUrl parmi ses programmes, détecte les overrides réels et les cas ambigus (égalité parfaite, tous vides). N'écrit rien dans Firebase.

2Écrire

Écrit applicationPortalUrl sur chaque université concernée, vide applicationUrl sur les programmes redondants avec le défaut, laisse les overrides réels intacts. Les universités en anomalie (étape 1) ne sont pas touchées.

3Vérifier (non négociable)

Recalcule la valeur effective de chaque programme après migration (applicationUrl du programme, sinon celui de son université) et la compare à la valeur d'avant migration. Doit afficher 0 perte de données (mismatch) pour considérer la migration réussie.

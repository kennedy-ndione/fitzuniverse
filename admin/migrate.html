Migration vers l'architecture relationnelle

Remplace le champ texte "université" sur les bourses par une vraie relation many-to-many (collections universities / scholarships / programs). Réservé aux administrateurs — cette page n'est liée depuis aucune navigation. À exécuter une seule fois, dans l'ordre des 3 étapes.

1Analyser (lecture seule, aucune écriture)

Lit les collections actuelles et calcule ce qui sera créé : universités dédupliquées, bourses consolidées, programmes (relations). N'écrit rien dans Firebase.

2Écrire les bourses nettoyées + les programmes + les profils bruts

Consolide scholarships en place (un document par bourse, plus de champ "université"), crée la collection programs (une entrée par offre université × bourse × niveau), et prépare les profils d'université dans une collection temporaire universities_draft — l'ancienne collection universities n'est pas encore touchée à cette étape, le site public continue de fonctionner normalement pendant que vous vérifiez le résultat.

3Finaliser — bascule universities

Étape destructrice, à ne lancer qu'après avoir vérifié le résultat de l'étape 2 (ex. dans la console Firebase). Supprime les anciens documents d'offres dans universities, puis y recopie les profils propres depuis universities_draft. C'est seulement après cette étape que le nouveau code (catalogue public + panneau admin mis à jour) doit être utilisé.
